# M1 source adapters: media and publications

This document defines the completed import boundary for the v2 portable state. The adapters are offline: they do not connect to Supabase, fetch publisher content, resolve signed URLs, or access credentials.

## Registry media adapter

The registry export may include optional `media_assets` on each case. Omitting the field remains valid for older v1 exports.

Each approved asset carries:
- Stable source-local `asset_ref`.
- `modality`, `media_type`, and MIME type.
- SHA-256 and byte length.
- Safe relative `storage_ref` inside the export bundle.
- Optional My Experience ordinal and frame/time interval.
- Optional `parent_asset_ref` to preserve lineage for extracted clips, frames or stills derived from a source video.
- Optional capture timestamp and non-identifying metadata.
- Explicit `export_authorized: true`.

Never place a signed URL, bucket secret, patient name, MRN, source database UUID, or free-text identifier in this manifest. `source_case_ref` must be a keyed pseudonym generated by the trusted registry exporter. Pseudonymization is not anonymization.

The registry adapter maps each asset to `PortableStateV2.source_artifacts`, linked to the case episode or the corresponding My Experience reflection. Parent/child artifact references preserve derived-frame and clip lineage. Media bytes remain outside the JSON state.

## Publication adapter

Input format: `surgical-intelligence-publication-import`, version 1.

The publication importer consumes the user's already-retained library export. It does not download PDFs or bypass access controls. It preserves:
- DOI, PMID, PMCID, title, authors, journal, year and version.
- Retention state (`kept`, `hidden`, `unreviewed`) and decision timestamp.
- Optional retained full-text file with MIME type, safe relative path, SHA-256 and byte length.
- Separately structured claims, including locator (page/table/figure/section), population, intervention, comparator, outcome, estimate, uncertainty, limitations, epistemic status and review state.

A paper record is not an evidence claim. Claims are not automatically endorsed: `review_state` and `epistemic_status` are retained as supplied. The adapter does not manufacture claims by summarising a PDF. A separate extraction/review process can populate the claim objects.

## CLI

Import publications into a new v2 state file:

```bash
si import-publications --input ./publication-import.json --state ./state-v2.json --output ./state-with-papers.json
```

Package all `available` artifacts (operative media and retained paper files) and the portable state into a directory. The command verifies actual bytes against both byte length and SHA-256 before copying:

```bash
si package-bundle --state ./state-with-papers.json --source-root ./registry-and-paper-export --output-root ./SurgicalIntelligenceBundle
```

Verify an existing bundle:

```bash
si verify-bundle --state ./SurgicalIntelligenceBundle/state-v2.json --bundle-root ./SurgicalIntelligenceBundle
```

The bundle uses the same relative `storage_ref` values as the state. No provider-specific object-store URL is required.

## Verification and boundaries

- Registry media metadata is validated for explicit authorization, modality, checksum shape, safe relative path and frame bounds.
- Publication files are validated for authorization, checksum shape and safe relative path.
- V2 validation requires every `available` artifact to have a relative path, byte length and SHA-256.
- `package-bundle` and `verify-bundle` check actual bytes, not just checksum syntax.
- Source registry implementation must still generate the authorized export from its own access/consent controls. This repository intentionally does not query or mutate the registry database.
- A portable bundle is still sensitive clinical material. Encrypt it at rest and in transit, restrict access, log exports, and apply retention/deletion policy. Do not place identifiable operative footage in a general-purpose knowledge bundle.
